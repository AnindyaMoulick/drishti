## 1. What We Are Building

A **vision screening web app for Indian school children**. A child uses it on their own on a phone to check:

1. **Visual acuity**: can they see small symbols clearly? (one eye at a time)
2. **Color blindness**: can they read numbers hidden in colored-dot plates?

At the end the child gets a simple **"vision looks healthy"** or **"please visit an eye doctor"** result. Every result is **saved on the device**, and a teacher can export them to Excel.

**What the app is meant to fix:** children in India come from many language backgrounds, so the whole app must work in their own language (all 22 scheduled languages of the Constitution). It should follow the WHO visual-acuity screening approach and work in a similar way to the **WHOeyes** app, where the symbol changes and gets smaller after each correct answer.

> ⚠️ It is a **screening tool, not a diagnostic device**. This disclaimer appears in the app.

### Added during the build (refinements)
- **Optional child name** screen (so saved results can be identified). Can be skipped.
- **Pass threshold:** each eye passes if acuity is **6/9 or better** (logMAR ≤ 0.2). The color test passes with **≥ 5 of 7** scored plates correct.
- **No minimum size for tiny symbols:** at arm's length, 6/6 is only about 0.6 mm, and forcing a bigger size would make the test wrong.
- **Answer buttons are shuffled for each eye**, so children can't memorise button positions.
- **Early pass:** if the first 2 of 3 symbols at a level are correct, the test moves on straight away.
- **Fail at the very first level** is recorded as `<6/60`.
- **Color test uses a keypad + OK button** (no auto-submit, which would reveal how many digits the answer has). Includes an "I can't see a number" button.
- **If the child misreads the practice plate** and fails, the color result is marked "inconclusive" instead of "red-green".
- **Calibration has +/− buttons** for fine adjustment (dragging is hard on small phones).
- **Fixed light theme**, so the phone's dark mode doesn't change test contrast.
- **CSV export** (opens in Excel with Indian-script names intact) in addition to JSON.

## 3. App Flow

```
Home → Language → Name (optional) → Age → Calibrate (Aadhaar card) → Instructions
     → Acuity: Right eye → "Switch eye" screen → Acuity: Left eye
     → Color test (8 plates) → Results (auto-saved) → History / New test
```

| Route | File | What it does |
|-------|------|--------------|
| `/` | `src/app/page.tsx` | Home: Start test / View past results |
| `/language` | `src/app/language/page.tsx` | Grid of 23 languages in their own scripts |
| `/name` | `src/app/name/page.tsx` | Optional name |
| `/age` | `src/app/age/page.tsx` | Age 6–14 button grid |
| `/calibrate` | `src/app/calibrate/page.tsx` | Aadhaar card box: drag handle + +/− buttons |
| `/instructions` | `src/app/instructions/page.tsx` | 4 steps, read aloud |
| `/test/acuity` | `src/app/test/acuity/page.tsx` | **Core test**: LEA symbols, two-step confirmation, LogMAR logic, both eyes |
| `/test/color` | `src/app/test/color/page.tsx` | Ishihara-style plates + keypad; saves the colour-only result at the end. Plates: numbers of plates 1–8 of the 38-plate Ishihara (12 demo, 8, 29, 5, 3, 15, 74, 6), drawn by `IshiharaPlate.tsx` with orange/yellow-green shade pairs checked by protan/deutan simulation (normal ΔE ≥ 53, CVD ΔE < 9 per pair). The printed Ishihara images are copyrighted, so they are not copied. |
| `/results` | `src/app/results/page.tsx` | Pass/fail cards per eye + color, read aloud |
| `/history` | `src/app/history/page.tsx` | All saved results, Excel (CSV) / JSON export, delete, clear all |

### Key numbers
- **Arm's length by age (cm):** 6→35, 7→37, 8→39, 9→41, 10→43, 11→46, 12→48, 13→51, 14→54
- **Symbol size formula:** size = 2·d·tan(5·10^logMAR arcmin / 2), converted to CSS px using the calibrated PPI, then ÷ 0.8 for the SVG's padding.
- **Color plates:** `12` (practice, orange-on-blue, visible to all), then `8, 5, 29, 74, 6, 45, 3` (scored).
- **Plate colors** were chosen with a color-blindness simulation (Machado 2009) so each figure/background pair looks clearly different to normal vision (ΔE≈35) and nearly the same to protan/deutan eyes (ΔE≈6). Each dot's brightness is also varied randomly, so brightness alone can't reveal the number. The search script is `scratch/cvd_palette.js` in the previous session's folder; the final values are hard-coded in `IshiharaPlate.tsx`.

### Data storage
- **Saved results:** `localStorage["drishti_results"]` = array of `TestResult`. Each one holds the id, timestamp, name, age, language, PPI, distance, every right/left eye answer + best Snellen/logMAR + pass, every color answer + pass/deficiency, and the overall pass.
- **Data passed between pages during a test:** `testMode` ('vision' | 'color') lives in app state; `sessionStorage['drishti_lastResultId']` points the results page at the saved result. `TestResult.rightEye/leftEye/colorVision` are optional: an eyesight result has no colour part and a colour result has no eye parts (old results saved before the split have all three).
- Data stays **on that device and browser only**; nothing is sent to a server.

### ⚠️ Medical / accuracy caveats to remember
- **Arm's length (35–55 cm) tests near vision.** WHO school screening normally uses distance vision (e.g. 6 m / 3 m). The results should be described as *near-vision screening*, or a distance mode could be added later.
- The **LEA symbol SVGs are approximations** of the official LEA shapes (which are licensed by Lea-Test Ltd).
- **The code-generated color plates are not clinically validated** against real Ishihara plates.
- Calibration accuracy depends on the child matching the card carefully.

```powershell
cd C:\Users\iammo\drishti
npx next dev -H 0.0.0.0 -p 3000      # dev server (LAN accessible)
npm run build                         # production build
npx tsc --noEmit --incremental false  # type check
```
- On this PC: http://localhost:3000. On a phone (same Wi-Fi): `http://<PC-IP>:3000`.

### Environment gotchas (learned the hard way)
- **PowerShell**: use `;`, not `&&`. `npm run dev -- -p 3000` drops the `--`, so call `npx next dev ...` directly.
- **Agent sandbox**: it can't write to `.next/` or `tsconfig.tsbuildinfo` (EPERM) and can't reach `localhost:3000`. `npm run build`, the dev server and the browser test must run **outside the sandbox** (needs approval).
- **`cacheComponents` forbids `Math.random()` during render** of prerendered client components (dev error "unstable value `Math.random()`"). Randomised state lives in a child component that renders only after hydration (see `test/acuity/page.tsx`).
- **Next.js 16.4** (Turbopack, `cacheComponents: true`, Tailwind v4 with `@import "tailwindcss"`). The project's `AGENTS.md` (from create-next-app) has Next 16 notes. Read it before changing framework-level code.
- Blocked phone origins show up as `Blocked cross-origin request … /_next/hmr` in the dev log → add the IP to `allowedDevOrigins` in `next.config.ts`.

## Changes 2026-11-12 (session 3)
- **Acuity symbols are now outline LEA-style symbols** (`src/components/LEASymbols.tsx`): the line is 1/5 of the symbol, the same rule as standard optotypes and the tumbling E used by WHOeyes. At 6/6 the symbol is 5 arc minutes and the line 1 arc minute. The old solid silhouettes blurred together at 6/9 and 6/6, so even normal eyes failed.
- **Minimum drawable size:** if a symbol's line would be under 2 real screen pixels, it is raised to that minimum (`MIN_LINE_DEVICE_PX` in the acuity page). On phones (devicePixelRatio 2-3) the 6/6 size stays exact. On a low-resolution laptop screen the smallest levels end up slightly larger than true size.
- **Ishihara digits** are drawn as even-width stroke paths (`DIGIT_PATHS` in `IshiharaPlate.tsx`, line width 7% of the plate) instead of a bold font.
- **Voice answers** in the colour test (`src/lib/speech.ts`): a "Say the number" button, then "You said N. Is that right?" with Yes / No. It reads native-script digits and English number words. Languages the speech service doesn't support fall back to en-IN. It needs HTTPS or localhost, and internet (Chrome uses Google's speech service). The button is hidden where the browser can't listen. The e2e test fakes the microphone.

- **Colour test voice is now hands-free.** After the child taps "Say the number" once, which is needed for the mic permission, each plate listens automatically. The app shows the heard number ("You said 29.") for 1.6 s, then moves to the next plate and listens again; there is no Yes/No step any more.
  - Saying "nothing" or "I can't see" (and the Hindi/Urdu equivalents) records no number.
  - After 3 silent or unclear tries the mic pauses and waits for a tap.
  - If the mic is blocked or offline, the app falls back to the keypad.
  - "Type the number instead" switches to the keypad.
  - The `color.heard` text lost its question in all languages, and `color.typeInstead` is new.
  - In the e2e test the fake mic takes answers from `window.__fakeQueue`.

- **The colour test now reports the likely type of colour blindness.** The test is 12 plates (see `src/lib/colorScoring.ts`):
  - Plate 1, demo (12): everyone should read it. A miss means the result is unclear and the test should be repeated.
  - Plates 2-8, red-green screening, as before: 5 of 7 correct passes.
  - Plates 9-10, classification (26 and 42, as in Ishihara plates 22-23), on grey dots:
    - The left digit is invisible to protan eyes, so a protan child reads only the right digit.
    - The right digit is invisible to deutan eyes, so a deutan child reads only the left digit.
    - Two one-sided answers mark protan or deutan even if screening passed.
  - Plates 11-12, blue-yellow (7 and 45): an olive digit on grey that tritan eyes can't see. These are not in the Ishihara book, which tests only red-green. Missing both suggests tritan.
- Possible results (`possibleDeficiency`), shown on a "Likely type" card on the results page and spoken aloud:
  - `none`
  - `protan` (red)
  - `deutan` (green)
  - `tritan` (blue)
  - `red-green` (type unclear)
  - `inconclusive`
- The plate colours were checked with the Machado 2009 simulation:
  - Each digit meant to be hidden has ΔE < 5 to the eye type it should fool.
  - The protan-hidden digit has only ΔE 24-26 for deutan eyes. That is near the most any colour allows, because protan and deutan confusion lines are close.
- 6 new `results.cvd*` keys were added in all 23 languages; they need native-speaker review.
